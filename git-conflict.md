# Git Conflict Resolution Log

## Где возник конфликт

- **Файл:** `src/main/resources/application.properties`
- **Строка:** значение свойства `server.port`
- **Ветка-источник:** `fix/conflict-demo`
- **Целевая ветка:** `main`

---

## Почему возник конфликт

Обе ветки независимо изменили одну и ту же строку конфигурации после точки расхождения:

| Ветка | Значение `server.port` |
|-------|-------------------------|
| `main` | `server.port=8081` |
| `fix/conflict-demo` | `server.port=9090` |

Git не может автоматически выбрать ни одну из версий, потому что обе строки
были изменены относительно общего предка (`server.port=8080`).
Это типичный **content conflict**: два параллельных изменения одного и того же фрагмента кода/конфигурации.

---

## Что видел Git в файле

```
<<<<<<< HEAD
server.port=8081
=======
server.port=9090
>>>>>>> fix/conflict-demo
```

- `<<<<<<< HEAD` — версия текущей ветки (`main`)
- `=======` — разделитель
- `>>>>>>> fix/conflict-demo` — версия входящей ветки

---

## Как разрешён

Маркеры конфликта удалены вручную; выбрано итоговое значение порта,
не совпадающее ни с одним из вариантов, чтобы не отдавать предпочтение
ни одной из веток и явно зафиксировать сознательное решение:

```
server.port=8090
```

---

## Команды, использованные при разрешении

```bash
# 1. Попытка merge — получили конфликт
git merge --no-ff fix/conflict-demo

# 2. Просмотр конфликтующих файлов
git status

# 3. Ручное редактирование application.properties:
#    удалить маркеры <<<<<<<, =======, >>>>>>>
#    оставить итоговое значение server.port

# 4. Пометить файл как разрешённый
git add src/main/resources/application.properties

# 5. Зафиксировать разрешение конфликта
git commit -m "fix: resolve merge conflict in application.properties"
```

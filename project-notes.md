# Project Notes — IT Hub Space

Архитектурные решения, компромиссы и договорённости команды.

---

## Выбор стека

### Почему Vanilla JS, а не React/Vue?

Команда выбрала Vanilla JS + Fetch API по двум причинам:

1. **Учебный контекст** — проект сдаётся в колледже; использование фреймворка
   без реального понимания DOM-операций маскирует пробелы в знаниях.
2. **Размер** — весь фронтенд укладывается в один `index.html` (~1500 строк).
   Настраивать Webpack/Vite ради одного файла — лишняя сложность.

Компромисс: при масштабировании (>10 страниц) поддержка усложнится;
тогда стоит перейти на легковесный фреймворк (Svelte или Preact).

---

### Почему JWT, а не сессии?

Spring Session потребовал бы Redis или БД-таблицу для хранения.
JWT позволяет обойтись stateless-проверкой прямо в `JwtFilter`
без дополнительного хранилища. Для учебного проекта это приемлемо.

Риск: нет механизма отзыва токенов до истечения срока.
Решение (на будущее): ввести таблицу `revoked_tokens` или перейти на Refresh Token.

---

### Почему PostgreSQL, а не H2/SQLite?

H2 in-memory теряет данные при перезапуске — неудобно для демонстраций.
PostgreSQL ближе к продакшн-среде; команда осваивает реальный инструмент.

---

## Структура БД — ключевые решения

- `data.sql` с `ON CONFLICT DO NOTHING` — безопасный idempotent-seed при каждом запуске.
- Все FK — `BIGINT REFERENCES`, без каскадного удаления (безопаснее для учебной среды).
- Таблица `buildings` хранит `city` и `address` отдельными полями — упрощает поиск через `ILIKE`.

## Git-workflow

Договорённости команды:

- Основная ветка разработки: `dev`; в `main` — стабильные релизы.
- Каждая фича — отдельная ветка `feature/*`, мержится через PR.
- Конвенция коммитов: `feat:` / `fix:` / `docs:` / `chore:` / `refactor:`
- Коммиты на русском языке — не используем (было решено после первого PR).

---

## Безопасность — открытые эндпоинты

Список публичных маршрутов прописан в `SecurityConfig.java`:

```java
.requestMatchers(
    "/api/events/**", "/api/faculties/**", "/api/buildings/**",
    "/api/media/**",  "/api/partners/**",  "/api/portfolios/**",
    "/api/auth/**",   "/static/**"
).permitAll()
```

Всё остальное — только с JWT. Это сознательный выбор:
читать контент может любой, изменять — только авторизованный.

## Известные ограничения

| # | Проблема | Статус |
|---|----------|--------|
| 1 | JWT не отзывается до истечения | Принято, не критично для учебного проекта |
| 2 | Нет пагинации у `/api/events` | Запланировано: `?page=&size=` |
| 3 | `data.sql` запускается при каждом старте | Решается через `spring.sql.init.mode=always` + `ON CONFLICT DO NOTHING` |
| 4 | Фронтенд — один файл `index.html` | Допустимо; при росте — разбить на модули |
